# 双堆滑动中位数后端（TypeScript + Node.js + SQLite）

定长数值窗口的在线中位数服务。连续接收整数样本，只保留最近 W 个样本作为有效窗口，
每次追加后报告当前中位数与窗口范围。纯后端实现，仅提供 HTTP API 与 CLI，
Windows 本地运行，不依赖 Docker / WSL / 外部服务。

## 快速开始

```powershell
npm install        # 安装 typescript 等开发依赖
npm run build      # 编译到 dist/
npm test           # 运行自动化测试（切片排序基准逐步核对）
npm run demo       # 运行演示（W=3 用例、偶数窗口、重复值、单调长序列）
npm start          # 启动 HTTP 服务，默认自动选择空闲端口
node dist/cli.js serve --port 8080   # 指定端口
```

要求 Node.js ≥ 22（使用内置 `node:sqlite`，无原生编译依赖）。数据保存在项目内 `data/` 目录。

## 核心算法

### 双堆结构
- 较小的一半放**最大堆**（lo），较大的一半放**最小堆**（hi）。
- 不变量：`loValid == hiValid` 或 `loValid == hiValid + 1`，且 `lo 堆顶 <= hi 堆顶`。
- 中位数：lo 多一个时取 lo 堆顶；相等时取两堆顶平均（**允许精确半整数**，如 2.5）。
- 每个样本有独立递增序号 `seq`，堆节点为 `{value, seq}`，相同数值的不同样本靠序号区分，过期时不会混淆。

### 有效长度 vs 物理长度
窗口滑过时，被删除的元素往往**不是堆顶**，无法立即从堆中移除，因此采用**惰性删除**：

- **有效长度**（`loValid` / `hiValid`）：单独维护的计数，只统计序号在当前窗口内的样本。
- **物理长度**（`loPhysical` / `hiPhysical`）：堆数组真实节点数，可能包含已过期但尚未浮到堆顶的“垃圾节点”。
- 读取边界、取中位数、移动堆顶**之前**必须先清理堆顶过期元素（`cleanTops`）。
- 过期归属判定：上一步结束时堆顶已清理，每步只有一个新过期元素，因此堆顶若非有效即为本步过期者，
  可精确判定过期元素属于哪一边并扣减对应计数。

### 定期重建（防止物理垃圾无限堆积）
单调输入会让过期元素埋在堆内越积越多。阈值规则：

> 物理节点总数 > W × 2 时，用当前有效样本重建两个堆。

重建记录原因与前后节点数量（见 `GET /runs/:id/report` 的 `rebuilds`），
不改变中位数与样本序号，保证长期物理状态有界（≤ 2W+1）。

### 窗口语义
- 样本按**接收序号**排列，不使用事件时间，无乱序 / 水位线 / 分组 / 近似分位数。
- 不足 W 个样本时按现有样本计算中位数，`windowFull=false`。
- 无数据时返回 `null` / `NO_DATA`，不返回 0 或 NaN。
- 窗口大小创建时固定，改变大小需新建运行。

## HTTP API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/runs` | 创建运行，body: `{"windowSize": 3}` |
| POST | `/runs/:id/append` | 追加，body: `{"value": 5}` 或 `{"batchId": "b1", "values": [1,2,3]}` |
| GET | `/runs/:id/median` | 当前中位数与快照（无数据返回 `NO_DATA`） |
| GET | `/runs/:id/state` | 两堆有效/物理大小、边界、重建日志 |
| GET | `/runs/:id/history?seq=4` | 按序号查历史结果；无参数分页返回（`limit`/`offset`） |
| GET | `/runs/:id/report` | 导出报告：配置、已处理样本数、快照、全部重建记录 |

每次追加返回：追加序号、离开窗口的序号与值、两堆有效/物理大小、边界元素、
中位数、窗口范围、是否装满、再平衡事件、重建事件。

### 错误码
`INVALID_WINDOW`（W 非 1..10000 整数）、`INVALID_VALUE`（值非 ±10 亿内整数）、
`EMPTY_BATCH`、`RUN_NOT_FOUND`、`SEQ_NOT_FOUND`、`BAD_JSON`。

### 批量与幂等
- 批量追加在 SQLite 事务中执行，任何一笔非法即整体回滚，已处理样本数不变。
- 携带 `batchId` 的批量请求幂等：同一 `(runId, batchId)` 重试直接返回首次结果，
  不会因重试把同一批样本多算一遍。

## 持久化与重启恢复
SQLite（`data/median.db`）保存：窗口配置（`runs`）、有效样本（`samples`）、
已处理序号与每步结果（`results`）、批次幂等记录（`batches`）、重建日志（`rebuilds`）。
进程重启后首次访问某运行时，按保存的最近 W 个有效样本重建双堆，
语义结果与重启前一致（不恢复已过期的物理垃圾节点，这本就是应清理之物）。

## 测试
`npm test` 使用独立的**切片排序基准**逐步核对每一步中位数，并校验：
有效数不超 W、两堆大小不变量、边界有序、序号连续。覆盖：
W=1、边界整数 ±1e9 与半整数、大量相同数值、过期元素埋在堆内（交替极值）、
单调长序列重建与状态有界、随机输入多窗口对照、参数校验、无数据状态、
SQLite 保存/重启恢复一致、批次幂等、批量失败原子回滚、HTTP 端到端。

## 查看清理证据
- `npm run demo` 演示 4 展示单调序列 1..100000（W=100）的重建过程：
  每次重建物理节点 201 → 100，最终物理节点有界，中位数逐步正确。
- 运行中通过 `GET /runs/:id/state` 观察 `loPhysical/hiPhysical` 与 `loValid/hiValid` 的差值（惰性垃圾），
  通过 `GET /runs/:id/report` 查看全部重建记录及原因。

## 已知限制
- 单进程内存态 + SQLite 持久化，未做分布式或多实例并发写同一运行。
- 历史结果接口默认限量分页（最大 1000 条/页），但所有真实样本都会被处理并落库。
- 重建阈值固定为 2 倍窗口容量（`src/median.ts` 中 `REBUILD_FACTOR`），可按需调整。
